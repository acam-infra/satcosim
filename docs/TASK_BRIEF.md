# 任务目标：天基大模型推理的动态算力路由仿真与优化（Task Brief）

> 来源：研究负责人 2026-11-11 下达（LAB-1779）。术语以 [`TERMS_AND_MODEL.md`](TERMS_AND_MODEL.md) 为准：原文「阴影区」= **凉星**（`cool`，迁入目标）；「日影 / 背阳」= **日影**（`eclipse` / `is_dark`，降频，迁出源）。
> 开发任务拆分见 [`HANDOFF.md`](HANDOFF.md)；架构收敛方案见 [`ARCHITECTURE_AND_TODO.md`](ARCHITECTURE_AND_TODO.md)。

**总体思路：** 构建一个纯数值的太空环境仿真器，采取「先暴露痛点（初次分配），再解决问题（二次重分配）」的故事线，核心验证**算力与传输的权衡（算-传 Trade-off）**。整体架构需模块化，方便替换不同场景和算法。

## 一、仿真底座搭建（工程要求）

- **纯数值仿真：** 不做复杂的物理级协议模拟，聚焦于任务流、延迟计算、吞吐量统计的数值仿真，快速跑通逻辑。
- **插件化架构（Pluggable）：** 将「底层环境（拓扑变化、发热模型）」与「上层策略（分配算法、路由算法）」解耦，预留标准接口，确保后续不同的场景设置和调度算法可以像插件一样随时接入和替换。

## 二、阶段一：实现初次分配 Baseline（立靶子、暴痛点）

- **算法实现：** 直接采用地面最基础的静态 / 无状态分配算法（如 Round Robin 轮询、就近分配）。
- **必须体现的 3 个场景特征（用于构造痛点）：**
  1. **请求局部性：** 模拟地面热点区域，让请求集中打向局部几颗卫星。
  2. **大模型长耗时：** 将任务建模为耗时较长、计算密集的 LLM 推理任务（而非短平快的普通请求）。
  3. **过热降频机制（关键）：** 设定温度阈值。连续长推理会导致卫星过热，触发降频（Thermal Throttling），算力断崖式下降。
- **阶段产出：** 跑出 Baseline 的劣化数据，验证在初次分配下会出现**局部严重拥塞、坏吞吐（超时 / 降频导致）飙升、以及 P95 延迟爆炸**的现象。

## 三、阶段二：设计二次再分配算法（核心创新点）

当节点负载过高或即将过热时，触发重调度。打破「只选最短路径」的传统路由，用**多跳传输的通信延迟**去换取**远端空闲节点的充沛算力**（算-传 Trade-off）。

- **算法需结合的「时变场景」：**
  1. **热力学与光照时变（主推）：** 卫星周期性进出日照与日影。算法需感知这种时变状态，把即将过热或进入日影的节点上的任务，多跳路由到**日照且凉的远端卫星（凉星，原文「阴影低温区」）**上；刚出日影的星热余量最大。
  2. **星间拓扑时变：** 卫星移动导致星间链路（距离、带宽）随时间变化。再分配时，需动态计算 `多跳传输耗时 + 远端推理耗时 + 结果回传耗时` 的最优解。
  3. **推理阶段动态迁移（可选拔高）：** 若本地节点算完 Prefill 后过热，可将后续耗时的 Decode 阶段（连同状态数据）迁移到远端空闲卫星继续算，权衡「状态传输开销」与「本地降频卡顿开销」。（注：现有 `CoWorld._migrate` 已实现带 KV 的 Decode 迁移。）
- **阶段产出：** 对比阶段一的 Baseline，证明时变再分配算法能显著提升全网算力利用率，**把有效吞吐（Goodput）提上来，把 P95 延迟打下去**。

## 四、可信性要求（审阅补充）

1. 参数有出处（硬件手册或文献），主要参数做敏感度扫描；
2. 所有对比策略共用同一组迁移配额与准入规则（`rebalance_invariants`）；
3. 结果按 seed 配对报差值，并报出新算法不占优的参数区间；
4. 算-传权衡只在链路窄、KV 大、链路间歇时出现，需用带宽 / KV 扫描（E3）画出交界线。
